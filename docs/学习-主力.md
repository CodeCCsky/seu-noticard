## 1. 五个心智模型（和 Python 最容易撞的地方）

### 1.1 编译单元与链接

Python 的 `import` 是运行时去磁盘找模块。C++ 的 `#include` 是**文本粘贴**：预处理器把 `.h` 的内容原样塞进 `.cpp`，然后每个 `.cpp` 单独编译成 `.obj`，最后链接成 `.exe`。

~~~
main.cpp ──编译──► main.obj ─┐
db.cpp   ──编译──► db.obj   ─┼──链接──► seu-noticard.exe
json.cpp ──编译──► json.obj ─┘
~~~

- 一个 `.cpp` + 它 include 的所有 `.h` = 一个**编译单元**；
- 声明（函数长什么样）放 `.h`，定义（函数体）放 `.cpp`；
- 声明可以出现很多次，**定义只能有一次**（ODR，One Definition Rule）；
- 改 `.h` → 所有包含它的 `.cpp` 全部重编。这就是"接口冻结"的原因；
- `LNK2019` = 你声明了、也调用了，但没人写函数体。

### 1.2 值语义

~~~cpp
std::string a = "abc";
std::string b = a;      // 复制！b 是新的内存
b += "d";               // a 仍然是 "abc"
~~~

Python 里 `b = a` 是同一个对象。C++ 默认复制。所以：

- 只读参数写 `const std::string&`，避免每次调用都复制；
- 要改参数写 `std::string&`；
- 返回值直接 `return`，编译器有移动语义，不用担心性能。

### 1.3 栈、堆、RAII

~~~cpp
void write_log() {
    std::ofstream f("a.txt");   // 栈对象，构造时打开文件
    f << "hello\n";
}                               // 离开作用域，析构函数自动关闭文件
~~~

- 栈对象随作用域自动销毁，不需要 `close`；
- `std::vector`、`std::string` 自己管内存，析构时释放；
- **不要写裸 `new/delete`**；Pimpl 用 `std::unique_ptr<Impl>`；
- 野指针、重复 delete、忘了 delete，是 C++ 最常见的崩溃来源。

### 1.4 错误处理：本项目不用异常

~~~cpp
bool parse_int(const std::string& s, int* out, std::string* err) {
    if (s.empty()) {
        if (err) *err = "empty string";
        return false;
    }
    *out = 0;
    for (std::size_t i = 0; i < s.size(); ++i) {
        if (s[i] < '0' || s[i] > '9') {
            if (err) *err = "not a number";
            return false;
        }
        *out = *out * 10 + (s[i] - '0');
    }
    return true;
}
~~~

调用方必须检查：

~~~cpp
int n = 0;
std::string err;
if (!parse_int(text, &n, &err)) {
    // 处理失败：记日志、标失败、跳过
}
~~~

约定：`bool` 返回、`err` 出参、失败时 `out` 不保证有值。别抛异常，也别静默返回 0。

### 1.5 头文件卫生

~~~cpp
// db.h —— 只放声明
#pragma once
#include <string>
#include <vector>
#include "model/types.h"

namespace nc {
class Db {
public:
    Db();
    ~Db();
    bool open(const std::string& path, std::string* err);
private:
    struct Impl;
    std::unique_ptr<Impl> p_;
};
}  // namespace nc
~~~

规则：

- `#pragma once` 防重复包含；
- 只 include 用得到的头文件；
- 头文件里**不要**定义普通函数/全局变量（会重复定义）；需要共享就放 `.cpp` 用 `static` 或匿名命名空间；
- 不写 `using namespace std;`（头文件里尤其禁止）。

### 1.6 字符串是字节

~~~cpp
std::string s = "中文";
std::cout << s.size();      // 6，不是 2
~~~

Python 的 `len("中文")` 是 2。C++ 里 `std::string` 是字节数组，一个汉字 3 字节（UTF-8）。

所以：

- 截断摘要必须按**码点**，不能 `s.substr(0, 200)`，否则会把汉字劈成两半；
- 大小写转换只能对 ASCII 做；
- 控制台输出中文前要 `SetConsoleOutputCP(CP_UTF8)`。

## 2. 语言子集速成

### 2.1 类型与初始化

~~~cpp
int n = 42;
long long ts = 1762000000LL;     // 时间戳
double ratio = 0.5;
bool ok = false;
char c = 'A';
std::string s = "hello";
~~~

统一初始化（推荐，能防窄化）：

~~~cpp
int n{42};
std::string s{"hello"};
std::vector<int> v{1, 2, 3};
~~~

### 2.2 引用与指针

~~~cpp
void by_value(int x)      { x = 99; }   // 副本，外面不变
void by_ref(int& x)       { x = 99; }   // 外面变
void by_const_ref(const std::string& s); // 只读，不复制

int a = 1;
by_ref(a);                 // a == 99
int* p = &a;               // 指针：可以为空
if (p) std::cout << *p;
~~~

本项目里指针只用于两处：`err` 出参、Pimpl 的 `unique_ptr`。其他一律引用。

### 2.3 `const` 的三种位置

~~~cpp
const std::string& s;        // 不能通过 s 改内容
std::string* const p;        // 指针本身不能改
int value() const;           // 成员函数不修改对象
~~~

### 2.4 类：构造、析构、const 成员、Pimpl

~~~cpp
class Stmt {                       // 包住 sqlite3_stmt*
public:
    Stmt(sqlite3* db, const char* sql);
    ~Stmt();                       // 自动 finalize
    bool ok() const { return st_ != nullptr; }
private:
    Stmt(const Stmt&);             // 禁止拷贝（C++11 可写 = delete）
    Stmt& operator=(const Stmt&);
    sqlite3_stmt* st_ = nullptr;
};
~~~

- 构造函数初始化成员，析构函数清理资源；
- 拷贝一个"持有资源"的对象通常要禁止，否则会 double free；
- Pimpl：头文件里只写 `struct Impl; std::unique_ptr<Impl> p_;`，把 WinHTTP/SQLite 藏在 `.cpp`，别的文件不用 include 系统头。

### 2.5 枚举

~~~cpp
enum class State { New = 0, Read = 1, Snoozed = 2, Dismissed = 3 };

State s = State::New;
if (s == State::New) { }
int n = static_cast<int>(s);       // 落库时转换
~~~

`enum class` 不会隐式转 int，也不会污染命名空间，比裸 `enum` 安全。

### 2.6 命名空间

~~~cpp
namespace nc {
namespace text {
std::string trim(const std::string& s);
}  // namespace text
}  // namespace nc
~~~

C++14 **不能**写 `namespace nc::text {}`（C++17 语法），必须嵌套。

## 3. 标准库速查

### 3.1 `std::string`

| 操作 | 写法 | 坑 |
|---|---|---|
| 长度 | `s.size()` | 返回 `size_t`，和 `int` 比较会有警告 |
| 查找 | `s.find("x")` | 找不到返回 `std::string::npos` |
| 子串 | `s.substr(pos, len)` | `pos` 越界会抛异常，先判 `pos <= s.size()` |
| 拼接 | `s += "x"` / `s.append(...)` | |
| 截断 | `s.resize(n)` | 按字节，会劈开汉字 |
| 比较 | `s.compare(i, n, "x") == 0` | 比 `substr` 少一次复制 |
| 转数字 | `std::stoi` | 会抛异常；本项目自己写解析 |
| 转字符串 | `std::to_string(n)` | 够用 |

### 3.2 `std::vector`

~~~cpp
std::vector<Item> items;
items.push_back(it);
items.size();
items[0];
for (std::size_t i = 0; i < items.size(); ++i) { }
for (const Item& it : items) { }      // C++11 range-for
~~~

**迭代器/引用失效**：`push_back` 可能重新分配内存，之前拿到的 `&items[0]` 全部作废。遍历时不要往里加。

### 3.3 `std::map` 与 `std::pair`

~~~cpp
#include <map>
#include <utility>

std::map<std::string, int> count;
count["jwc"] += 1;

std::vector<std::pair<std::string, int>> rails;
rails.push_back(std::make_pair("jwc", 9));
~~~

`std::pair` 在 `<utility>` 里，别指望 `<vector>` 一定带进来。

### 3.4 读文件

~~~cpp
#include <fstream>
#include <sstream>

std::string read_all(const std::string& path) {
    std::ifstream in(path.c_str(), std::ios::binary);
    if (!in) return std::string();
    std::ostringstream ss;
    ss << in.rdbuf();
    return ss.str();
}
~~~

C++14 里 `ifstream` 只接受 `const char*`，所以 `.c_str()` 不能省。

### 3.5 时间

~~~cpp
#include <ctime>

std::time_t now = std::time(nullptr);
std::tm* tm = std::localtime(&now);
int y = tm->tm_year + 1900;
int m = tm->tm_mon + 1;
~~~

- `localtime` 不是线程安全的，但本项目只有主线程和调度线程各调一次，问题不大；
- 日期字符串自己拼，别用 `strftime` 的本地化；
- 时区：中国没有夏令时，`mktime` 够用。

## 4. 四块硬骨头

### 4.1 WinHTTP（HTTP 客户端）

调用顺序固定，背下来：

~~~
WinHttpOpen
  → WinHttpConnect(host, port)
    → WinHttpOpenRequest(GET, path)
      → WinHttpSendRequest
        → WinHttpReceiveResponse
          → WinHttpQueryHeaders(状态码/Content-Type)
            → 循环 WinHttpReadData 直到返回 0
              → 逐层 WinHttpCloseHandle
~~~

要点：

- URL 必须是宽字符：`MultiByteToWideChar(CP_UTF8, ...)`；
- 头文件 `<winhttp.h>`，库 `winhttp.lib`；
- 失败时 `GetLastError()` 拿错误码，`FormatMessage` 转文字；
- 代理用 `WINHTTP_ACCESS_TYPE_DEFAULT_PROXY`；
- 重定向默认跟随，但 `final_url` 自己记一下。

最小骨架（伪代码，不要照抄）：

~~~cpp
HINTERNET s = WinHttpOpen(ua, WINHTTP_ACCESS_TYPE_DEFAULT_PROXY, ...);
HINTERNET c = WinHttpConnect(s, host_w, port, 0);
HINTERNET r = WinHttpOpenRequest(c, L"GET", path_w, ...);
WinHttpSendRequest(r, headers, ...);
WinHttpReceiveResponse(r, nullptr);
DWORD code = 0, len = sizeof(code);
WinHttpQueryHeaders(r, WINHTTP_QUERY_STATUS_CODE | WINHTTP_QUERY_FLAG_NUMBER, ...);
// 循环 ReadData
WinHttpCloseHandle(r); WinHttpCloseHandle(c); WinHttpCloseHandle(s);
~~~

### 4.2 WinSock（HTTP 服务端）

~~~
WSAStartup
  → socket(AF_INET, SOCK_STREAM, 0)
    → bind(127.0.0.1:8787)
      → listen
        → accept
          → recv 循环读到 \r\n\r\n
            → 处理请求
              → send 循环
                → closesocket
~~~

要点：

- `#include <winsock2.h>` 必须在 `<windows.h>` 之前，否则 `winsock.h` 重定义；
- `send` 可能只发出去一部分，要循环；
- `recv` 可能一次收不全，POST 的头和体可能分两个包到达；
- 响应加 `Connection: close`，处理完就关；
- 端口被占用（10048）就换一个端口重试。

### 4.3 SQLite C API

~~~cpp
sqlite3* db = nullptr;
sqlite3_open("data/seu-noticard.db", &db);
sqlite3_exec(db, "PRAGMA journal_mode=WAL;", nullptr, nullptr, nullptr);

sqlite3_stmt* st = nullptr;
sqlite3_prepare_v2(db, "INSERT INTO items(url) VALUES(?)", -1, &st, nullptr);
sqlite3_bind_text(st, 1, url.c_str(), -1, SQLITE_TRANSIENT);
int rc = sqlite3_step(st);          // SQLITE_DONE / SQLITE_ROW
sqlite3_finalize(st);
~~~

要点：

- 每个 `sqlite3_stmt*` 用完必须 `finalize`，用 RAII 包住；
- `bind_text` 的最后一个参数用 `SQLITE_TRANSIENT`，让它复制字符串，别传 `SQLITE_STATIC` 接一个临时对象；
- `prepare` 的 SQL 里不要拼字符串，用 `?` 占位符，防注入；
- 错误信息：`sqlite3_errmsg(db)`；
- 后台线程 + 主线程各开一个连接，开 WAL 和 `busy_timeout`。

### 4.4 手写 JSON 解析（递归下降）

思路：

~~~
parse_value:
  skip_ws
  '{' → parse_object
  '[' → parse_array
  '"' → parse_string
  't'/'f' → true/false
  'n' → null
  数字 → parse_number
~~~

- 维护一个 `pos` 下标，所有函数围绕它前进；
- 出错时记录 `line/col`：扫描到 `pos` 时数换行；
- 字符串要处理 `\uXXXX` 转义；
- 序列化时中文可以直接输出 UTF-8，但 `"`、`\`、换行、控制字符必须转义。

### 4.5 手写 HTML 扫描

**标签扫描**（状态机）：

~~~cpp
bool in_tag = false;
for (char c : html) {
    if (c == '<') { in_tag = true; continue; }
    if (c == '>') { in_tag = false; continue; }
    if (!in_tag) out += c;
}
~~~

真实版本还要：

- 遇到 `<script` / `<style` 就整段跳到对应的 `</script>` / `</style>`；
- `<br>`、`</p>`、`</td>`、`</tr>`、`</div>` 输出换行；
- 属性值**单引号、双引号都认**（实测教务处 15/15 是单引号）；
- 找正文区时做**配平 div**：从 `<div class="wp_articlecontent">` 开始，数 `<div` 和 `</div>`，深度归零时结束。

**日期提取**：先找 `20\d\d[-/.年]\d{1,2}...` 的模式，别一上来写完整解析器。

## 5. 线程最小集

本项目只需要一个后台调度线程：

~~~cpp
#include <atomic>
#include <thread>

std::atomic<bool> g_stop(false);

void worker() {
    while (!g_stop.load()) {
        // 抓一轮、睡 3 秒
    }
}

std::thread t(worker);
// ... 主线程服务 ...
g_stop.store(true);
t.join();
~~~

规矩：

- 线程里不碰 UI 状态，要显示进度就查数据库；
- 一个 `Db` 对象只给一个线程用；
- `join` 必须在对象析构前；
- 别在线程里 `std::cout` 满天飞，日志加锁或只从一个线程打。

## 11. 自测 12 题

1. `#include` 和 Python 的 `import` 本质区别是什么？
   → 文本粘贴 vs 运行时加载；前者产生编译单元。
2. 为什么头文件里不能定义普通函数？
   → 多个 `.cpp` 包含会重复定义，链接报 multiple definition。
3. `const std::string&` 和 `std::string` 参数的区别？
   → 不复制 vs 复制。
4. 什么是 RAII？举一个本项目里的例子。
   → 构造获取、析构释放；`Stmt` 析构时 `finalize`。
5. `std::string s = "中文"; s.size()` 等于多少？
   → 6。
6. 为什么 `s.substr(0, 200)` 不能用来截摘要？
   → 按字节切，可能劈开汉字。
7. `LNK2019` 的三种常见原因？
   → 没实现、.cpp 没加进工程、库没链接。
8. SQLite 的 `bind_text` 为什么用 `SQLITE_TRANSIENT`？
   → 让 SQLite 复制字符串，避免悬空指针。
9. 为什么 `winsock2.h` 要在 `windows.h` 前面？
   → 否则 `windows.h` 会先引入 `winsock.h`，导致重定义。
10. 后台线程和主线程能共用一个 `Db` 对象吗？
    → 不能，各开一个连接；开 WAL。
11. `enum class` 和 `enum` 的区别？
    → 强类型、作用域受限、不隐式转 int。
12. `vector` 的 `push_back` 之后，之前的 `&v[0]` 还能用吗？
    → 不保证，可能重新分配。
